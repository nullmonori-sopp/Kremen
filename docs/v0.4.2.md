# Kremen 0.4.2: learning material and useful error locations

Released on 2026-10-22. This patch makes the existing language easier to learn and makes failures easier to locate. It does not add new language syntax or expand the self-hosted subset into the full language.

## English documentation with a starting point

Every Markdown page has been rewritten in English, including historical release notes, installation, safety, benchmarks, and bootstrap documentation. The writing introduces terms before relying on them and distinguishes complete programs from fragments.

New readers can follow [Your first program](getting-started.md), then [ten guided lessons](tutorial.md). The lessons cover variables, decisions, loops, functions, arrays, structs, input, results, enums, tuples, references, slices, arenas, files, and deferred cleanup. Ten complete source files live in `examples/tutorial/`; tests check their output, both integer-input paths, and written file contents.

[Understanding errors](diagnostics.md) explains source locations, common mistakes, borrow notes, runtime failures, and backend messages. The [documentation map](README.md) helps experienced and first-time programmers choose a path. Older general examples now use English output too.

## Compiler diagnostics

Native errors show a numbered source excerpt and underline the offending token. Tabs are expanded; UTF-8 continuation bytes do not add caret cells. Long lines are clipped around the token before calculating slice lengths. This fixes an out-of-bounds diagnostic read when the token was far beyond the old clipping limit.

Common failures get short help text. Borrow conflicts identify the earlier loan, and local shadowing identifies the earlier declaration. Missing source files name their path in the standard diagnostic header.

The bootstrap frontend now tracks the start of each expression for type checking. A mismatch in an initializer or return points at that expression instead of the next token, which could be on another line. Undefined names and calls point at their name. The runtime renders bounded excerpts from the already-read compiler input. The C seed was regenerated and its fixed point verified.

A failed input reread clears the cached excerpt, so a removed or unreadable file cannot produce a diagnostic showing its previous contents.

## Runtime diagnostics

The full compiler embeds an immutable table of paths, line/column positions, and bounded excerpts. Safety checks pass a location ID; a failing check resolves it for reporting. Successful checks do not perform a table lookup or update mutable location state.

Arithmetic failures, bounds checks, stale memory, result access, user panic, and deferred operations can therefore identify the original `.kr` operation, including an imported file. Reports work after moving an executable or deleting its source. Deferred callbacks retain owned location tokens rather than addresses of temporary generator nodes.

The table increases generated C and binary data size. It retains build-time source paths and small source excerpts. It is not a call stack. Columns count bytes; wide/combining Unicode display remains approximate. The subset's generated arithmetic errors retain basename/line/column reporting, without embedded excerpts.

## Installation and validation

The installer includes saved benchmark reports alongside the documentation that links to them. Its tests also verify the installed tutorial example's output. Compiler flags remain strict, and runtime checks remain enabled at all optimization levels.

[Validation](validation.md) records the regression, sanitizer, installation, and archive checks. [Repository update instructions](repository-update.md) list additions and replacements for both 0.4.1 and this patch. [0.4.1 notes](v0.4.1.md) describe the preceding stabilization work in detail.
