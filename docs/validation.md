# Проверка Kremen 0.4.0

Среда выпуска: 21 октября 2026 года, Linux x86-64, GCC 14.2.0, POSIX shell. Основной компилятор и генерируемые программы используют `-std=c11 -Wall -Wextra -Wpedantic -Werror`; стандартная оптимизация — `-O3`. Начальные стадии bootstrap собираются с `-O2`. Clang в среде не установлен.
Итог выпуска: 172 проверки прошли (58 + 29 для полного языка, 53 семантические, 26 драйвера, 6 загрузки исходников). Пройдены фиксированные точки seed и compiler+driver, ASan/UBSan, установка/перенос/удаление и чистая сборка с самопересборкой после распаковки архива. Проверка утечек исключена по условиям среды, указанным ниже.

## Воспроизводимые команды

```sh
make test
make test-sanitize
make test-install
make examples
make bench
sh bench/check.sh
```

`make test` включает 58 прежних интеграционных проверок, 29 регрессий языка 0.3, 53 проверки типов bootstrap, 26 проверок его драйвера и шесть проверок загрузки специальных файлов. При чистой сборке воспроизводится seed → stage1 → stage2 → stage3; C-исходники всех стадий должны совпасть побайтно, пример должен вывести `720|18|ok`, четыре ошибочных исходника — получить нужную диагностику.

## Полный язык

Прежние 58 + 29 сценариев проверяют типы, методы, числовые границы, массивы, ссылки, порядок вычисления, `!T`/`?`, срезы, модули/заголовки, форматтер, `defer`, `catch`, арены, файловую систему, enum/match и кортежи. Ошибки исходников должны иметь адресную диагностику, нарушения runtime — завершаться с конкретной причиной. Форматирование проверяется на повторяемость, сохранение типов и поведения.

Арены проверяются после reset/free/выхода из блока, включая lvalue, память которого освобождена правой частью присваивания. Defer проверяется на LIFO, ранний захват аргументов, выходы циклов, `?`, panic в вызываемой функции и удержание изменяемого заимствования. Файловые проверки включают бинарные строки, закрытые дескрипторы и NUL в пути.

## Bootstrap и драйвер

`tests/selfhost/semantics.sh` проверяет типы, вызовы, арность, имена, области видимости, lvalue, дубликаты, глобальные инициализаторы, точку входа, достижимость и возврат. Положительные программы проверяют взаимную рекурсию, границы i64 и строковые литералы. Ошибочные программы должны отвергаться самим Kremen frontend и сохранять предыдущий C-артефакт. Отдельные регрессии закрывают конфликты с C-заголовками и триграфы C11.

`tests/selfhost/toolchain.sh` содержит 26 проверок. Проверяются строгие C-флаги и `-O3` по умолчанию, `--cc` и `-O0`, пути с пробелами, буквальные shell-метасимволы в argv, статусы 7/127/143, сохранность предыдущего вывода при frontend/backend ошибках, защита исходников через симлинки/жёсткие ссылки и защита ресурсов/исполняемого файла. Самопересборка должна побайтно воспроизвести C компилятора и драйвера следующей стадии; пересобранный драйвер проверяет и запускает программу.

`tests/native/source_io.sh` проверяет немедленный отказ от FIFO в основном frontend, форматтере, заголовках, импортах, bootstrap-трансляторе и новом драйвере. Команды ограничены watchdog `timeout` из coreutils: зависание считается ошибкой. Проверяется также сохранность артефакта и удаление временного каталога после диагностики.

## Санитайзеры

`make test-sanitize` сначала проверяет compiler/driver bootstrap и их C-слой ОС под AddressSanitizer и UndefinedBehaviorSanitizer, включая типизацию, обработку ошибок и самопересборку. Затем инструментируется основной C-компилятор и выполняются 87 проверок; отдельно инструментируется сгенерированный C для 29 регрессий 0.3 и семи сценариев присваивания в срез. Ожидаемая ошибка языка должна оставаться диагностической остановкой без отчёта санитайзера.

В управляемой среде LeakSanitizer отключён (`ASAN_OPTIONS=detect_leaks=0`), поэтому утечки этим результатом не проверены. На поддерживаемом хосте можно запустить `ASAN_OPTIONS=detect_leaks=1 make test-sanitize`. По умолчанию `UBSAN_OPTIONS=halt_on_error=1`.

## Установка и исходный архив

`make test-install` устанавливает оба компилятора в временный префикс с пробелами, проверяет `kremen selfhost`, запуск и выбор установленного runtime. Затем переносит префикс, запускает bootstrap-программу, обновляет установку, проверяет отказ при повреждённом манифесте и чужом занятом пути и удаляет Kremen с сохранением посторонних файлов.

```sh
make dist
unzip ../kremen-v0.4.0.zip -d /tmp/kremen-release-check
cd /tmp/kremen-release-check/kremen
sha256sum -c SHA256SUMS
make
make selfhost
make test-install
```

Архив содержит исполняемый `install.sh`, исходники, Markdown-документацию, тесты и C seed. Проверяются SHA-256, отсутствие Python/кешей/результатов сборки, чистая сборка из распакованного дерева, установка, перенос и команды нового драйвера. Побайтная фиксированная точка относится к подмножеству bootstrap, а не к полному frontend основного языка.

Микротест копирования проверяет 16768 комбинаций длины/выравнивания. Измерения frontend: [bench/check-results.txt](../bench/check-results.txt), методика — [bench/README.md](../bench/README.md). Тесты не являются доказательством отсутствия всех ошибок или универсальной гарантией производительности. Границы: [safety.md](safety.md), дальнейшие этапы: [selfhosting.md](selfhosting.md).
