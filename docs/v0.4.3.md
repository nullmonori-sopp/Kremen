# Kremen 0.4.3: worker threads and compiler hardening

This release adds native POSIX worker threads to the full language, fixes compiler correctness defects, and extends diagnostics for people and editor tools. The full compiler still lowers through C11. The self-hosted subset remains smaller and does not gain the threading API.

## Native workers with a checked boundary

`threadSpawn(worker, argument)` starts a named Kremen `func(i64) i64` function and returns `!thread`. `threadJoin(handle)` returns `!i64`; `threadClose(handle)` supplies idempotent deferred cleanup. Spawn failure and join failure are ordinary result values. Generated programs are linked with `-pthread`.

Workers receive copied integers. They cannot capture local variables or receive shared references, slices, pointers, or resource handles through this interface. Thread handles stay with their creator and cannot be returned or stored in composites. Runtime bookkeeping and defer stacks are thread-local. Creator exit joins outstanding children rather than abandoning them.

A panic in a worker runs that worker's cleanup and is reported to its joining creator as `ECANCELED`. A main-thread panic still terminates the process after joining children. There is no forced cancellation, timed join, detached execution, or general shared-memory API. The [thread guide](threads.md) gives a complete example and explains these choices.

## Checker and code generation

The backend no longer removes an array expression's effects or checks when a constant array length appears inside unary negation. An expression such as `-len(values[index])` must still evaluate `index` and check the access, even though the selected inner array's length is known. The optimizer now distinguishes a known result from an expression that can safely be skipped.

Result and slice layout calculations follow the actual generated C field alignment. On the tested LP64 host, the previous estimate counted `!i8` as 24 bytes instead of 16, and a slice descriptor as 32 bytes instead of 24. Those estimates could incorrectly reject an otherwise valid value near the 1 MiB layout limit. Type layout results are cached, and the backend uses hashed structural type lookup instead of scanning every previously seen type for a new equivalent type.

These changes reduce repeated compiler work; they do not establish a universal application speedup. Safety checks and left-to-right evaluation remain part of the language at every optimization level. [Benchmarks](../bench/README.md) distinguish the historical measurements from work in this release.

The runtime also indexes creator-owned thread handles instead of linearly searching every retained handle on join or close. The bounded index gives amortized constant-time lookup while keeping completed handle records available for stale-copy checks. This trades additional per-creator metadata for predictable lookup work.

## Diagnostics for a reader and an editor

Text diagnostics show surrounding source context, underline related declarations or loans, and include import-origin notes when an imported source caused the error. Unknown variables, functions, imported functions, types, fields, methods, and variants can receive a unique nearby-spelling suggestion. A typo in an imported function name is now reported as that lookup failure rather than an unknown module variable. Invalid NUL bytes in a source are located at their actual byte position rather than always at line 1, column 1.

`--diagnostic-format=json` emits one structured frontend error object on stderr. It includes the error code, message, byte range, excerpt, optional hint, related locations, and import locations. `--diagnostic-format=text` selects the default readable format. JSON output does not convert runtime or external C-compiler messages. The frontend still stops at the first error.

The source excerpts remain bounded for long lines. Header columns count bytes, while caret rendering handles tabs and UTF-8 continuation bytes. Wide and combining characters can still have terminal-dependent visual width. Read [Understanding errors](diagnostics.md) for the format and examples.

## Release contents and compatibility

Current documentation explains the threading boundary and updates source-build instructions for POSIX threads. The source distribution retains the C seed needed to bootstrap without an existing Kremen compiler. Historical 0.4.1 and 0.4.2 notes keep their original version context.

Old valid single-threaded programs keep their syntax. Calling the C compiler manually on emitted full-language code now requires `-pthread`. A worker panic has thread-local termination semantics; main-thread panic keeps process-level termination. Thread results and retained handle records add runtime costs, and automatic joins can wait indefinitely for a nonterminating worker.

[Validation](validation.md) records the implemented regression and sanitizer checks. [Repository update instructions](repository-update.md) explain source updates and generated files that belong in version control.
