# Kremen 0.3.0

Released on 2026-10-20. This release brought scoped resource cleanup, result fallbacks, arenas, filesystem operations, algebraic data types, matching, and tuples into the full language. The implementation and package used C, assembly, Kremen, and shell; the historical Python implementation and its tests were removed.

| Feature | Meaning |
| --- | --- |
| `defer cleanup(value)` | Capture arguments now; call in reverse order at block exit |
| `operation() catch fallback` | Extract success or lazily compute a replacement |
| `operation() catch code => fallback` | Also bind the failure code in the fallback |
| `arenablock memory { ... }` | Automatically release an arena at scope exit |
| `type E enum { A; B(value i64) }` | Tagged alternatives with payloads |
| `match value { ... }` | Check coverage and payload bindings |
| `(i64, string)`, `(1, "x")` | Tuple type and value |
| `var (number, text) = pair()` | Evaluate once and destructure a tuple |

Arenas zero-fill allocations; manual operations require `unsafe`. Slice access checks detect stale data after reset or free, including a recheck after assignment right-hand-side evaluation. Filesystem operations return results with positive OS error codes. `fileClose` provides idempotent deferred cleanup; `fsClose` returns a result.

The formatter and regression suites were extended for these constructs. Source archives gained an installer, executable-relative runtime lookup, ZIP/tar.gz packaging, and SHA-256 manifests.

Programs from 0.2 kept their basic syntax, but names such as `arena`, `file`, `enum`, `match`, `defer`, `catch`, and `arenablock` became reserved. Old Python-module commands, `make legacy-test`, and `bench/check.sh --legacy` no longer apply.

Panic recovery, implicit user destructors, nested/literal patterns, and full self-hosting were not part of this release. Use the [current reference](language.md) for exact present-day behavior and [the tutorial](tutorial.md) for a guided introduction.
