# Выпуск Kremen 0.3.0

Версия объединяет scoped-очистку ресурсов, лёгкие результаты ошибок, арены, файловый API и составные значения. Основная реализация — C11, дополнительно небольшой Asm-модуль копирования; сборка и тесты используют shell. Историческая Python-реализация удалена из пакета.

## Новые конструкции

| Конструкция | Поведение |
| --- | --- |
| `defer cleanup(value)` | Немедленный захват аргументов; LIFO-выполнение при выходе из блока |
| `operation() catch fallback` | Успешное значение либо лениво вычисляемая замена |
| `operation() catch code => fallback` | То же с локальным кодом ошибки `i64` |
| `arenablock memory { ... }` | Арена автоматически освобождается на выходе |
| `type E enum { A; B(value i64) }` | Тегированный union с конструктором `E.B(1)` |
| `match value { A => {}; B(n) => {} }` | Проверка типов, повторов и полноты вариантов |
| `(i64, string)`, `(1, "x")` | Тип и значение кортежа |
| `var (n, text) = pair()` | Однократное вычисление и деструктуризация |

Арены выделяют обнулённые значения; ручные операции требуют `unsafe`. Срезы после reset/free проверяются перед чтением и записью, включая повторную проверку после вычисления правой части присваивания.

Файловые функции возвращают `!T` с положительным кодом ОС. `fileClose(handle)` — идемпотентная очистка для `defer`; `fsClose(handle)` возвращает проверяемый результат. Ошибки нельзя игнорировать выражением вызова функции с результатом.

## Примеры и миграция

```sh
make
./build/kremen run examples/algebra.kr
./build/kremen run examples/resources.kr
make test
```

Старые программы 0.2 продолжают поддерживаться. Новые имена `arena`, `file`, ключевые слова `enum`, `match`, `defer`, `catch`, `arenablock` заняты языком. Переименуйте совпадающие локальные имена. `.kr` и `.krh` сохраняют назначение; новых расширений для enum/кортежей нет.

Вместо запуска старого Python-модуля используйте `build/kremen` или установленный `kremen`. `make legacy-test` и `bench/check.sh --legacy` удалены. Действующие команды приведены в [README](../README.md), полный синтаксис — в [справочнике](language.md).

`panic` вызывает отложенную очистку и завершает процесс. Перехват `panic` и `recover` отсутствуют; для ожидаемых ошибок используйте `!T`, `?`, `catch` или `match`. Пользовательские неявные деструкторы, вложенные/литеральные паттерны и полный self-hosting основной реализации не входят в этот выпуск.
