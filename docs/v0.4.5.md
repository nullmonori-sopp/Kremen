# Kremen 0.4.5: security hardening and checking profiles

This release adds the first usable `work` and `learn` profiles and fixes three reproduced problems in the full toolchain: exponential method-tree traversal, source loading outside a selected project root through symlinks, and unsafe terminal rendering of source-controlled text. The fixes apply to both profiles.

## First learning profile

Use `--mode=work` for ordinary checking or `--mode=learn` for the five additional requirements described in [Work and learn profiles](profiles.md). Work remains the compatible default. The learning pass runs after shared semantic checks and leaves the typed tree's lowering behavior unchanged. Accepted source emits byte-identical C in both profiles with the same options.

Learning requires explicit local initialization, observation or propagation of result-bearing values, used error codes in `catch` and `fail` patterns, explicit match cases, and fallible integer input. Result-discard checks include by-value aggregates and cache shared type graphs. Five new codes, `L001` through `L005`, have offline explanations; the full catalog now has 44 entries.

These are bounded structural requirements. They do not constitute a complete error-flow, ownership-transfer, or nonzero-divisor proof. Project profile files, `kremen learn`, and an interactive lesson system remain future work. The self-hosted subset does not gain these profiles.

## Method chains now traverse the syntax once

After checking a method call, the AST's receiver points to its existing callee base. Two backend walks followed both edges. A chain of calls therefore caused repeated traversal with exponential growth even though the source and syntax depth were small. A 30-call reproducer exceeded a three-second command deadline on the release environment.

Type scanning and defer-callback discovery now follow the syntactic edge once. The new learning pass follows the same ownership rule. Regression tests emit, compile, and run 90-call chains in both profiles, with and without deferred method calls. They check the result and capture/cleanup order under a deadline. This is a correction to compiler work for that shape of program, not a general application speedup claim.

## Canonical project boundaries cover every source

Import expressions already checked resolved paths, but directory-module entries and automatically paired `.krh` files could follow symlinks outside the project root without the same check. Every loaded implementation and header now receives a canonical boundary check. The entry module also respects an explicit root, and `--root` must name a directory.

Internal symlinks remain supported. A deliberate wider `--root` can admit the same files when it includes their canonical paths. This changes behavior for projects that relied on the bypass or selected a root excluding the entry module; select a common ancestor explicitly. The boundary is a source-resolution rule, not an OS sandbox or a guarantee against concurrent filesystem replacement.

## Diagnostic text cannot issue source-controlled terminal commands

The frontend escapes controls, direction-changing Unicode, and invalid UTF-8 bytes in displayed paths and messages while retaining ordinary readable UTF-8. Source excerpts replace unsafe scalars with visible cells, keeping the original byte ranges. Text messages now share the JSON renderer's 4,096-byte formatting buffer and truncation marker.

JSON keeps original path/range information and escaped invalid-byte data. It also escapes direction-changing characters and gains an additive `mode` field. The `catch` operator now carries its own source token, so its errors mark `catch` rather than the call to its left.

Runtime source paths use the same control policy without allocation, and embedded runtime excerpts use safe display text. Program-owned output and panic messages keep their string semantics. Late OS failures and external C-tool output remain outside the frontend renderer.

## Validation and compatibility

The regular suites contain 741 checks: the 419 previous checks, 41 profile cases, 25 security cases, and 256 deterministic mutation/profile combinations. The mutation corpus has 128 reproducible inputs and a fixed seed. Each accepted input must emit C that passes strict syntax checking; each rejected input must return a valid JSON error. Deadlines reject crashes and runaway compiler work. This is a targeted regression corpus, not evidence of exhaustive fuzz coverage.

ASan/UBSan exercise the compiler, new checks, diagnostic helpers, and selected generated programs. The 16 thread-runtime scenarios also run under ThreadSanitizer. Installation tests check profiles and explanations before and after prefix relocation. [Validation](validation.md) records commands and limitations; [repository updates](repository-update.md) lists release files.

Strict C flags, arithmetic and lifetime checks, the integer worker boundary, and the verified bootstrap compiler seed remain in place. The subset driver's version changes to 0.4.5. Saved earlier performance reports retain their original version context.
