# Kremen 0.4.1: stabilization and allocation work

Released on 2026-10-22. This is the release immediately before the documentation and diagnostics update in [0.4.2](v0.4.2.md). It kept the 0.4 syntax while fixing safety checks, reducing temporary allocation, and improving toolchain portability. The full frontend remained C; the subset compiler and CLI could reproduce themselves in Kremen.

## Borrowing and program behavior

`catch` now releases only its own operand's temporary loans. It preserves loans held by an enclosing expression or call. A fallback could previously let a second mutable access slip past an outer borrow.

Raw pointers created from shared references retain read-only provenance. Writing through `raw(&value)`, or passing it to a writable `*T` parameter, is rejected. Use `raw(&mut value)` for intended mutable access.

The formatter preserves `if`/`else` when block comments occur between branches. Regression checks compare behavior before and after formatting and verify idempotence. Qualified pattern parsing also avoids repeatedly copying growing name prefixes.

## Bounded compiler work

The compiler arena has a 512 MiB budget, and a file has a 1,000,000-token limit. String/vector size arithmetic is checked before allocation. Existing depth limits remain. Exceeding these limits produces a diagnostic instead of relying on a huge allocation or overflow.

The native CLI rejects ignored or incomplete options, supports `--` before a dash-leading source path, and protects sources, the selected runtime, and the executing compiler from output overwrite, including hard-link aliases. Dash-leading output paths are handled safely during C-backend staging.

## Bootstrap correctness

Function-body operands and arguments are lowered through explicit temporaries in left-to-right order. `&&` and `||` remain lazy. Loop conditions run on every iteration, including after `continue`.

Checked `i64` helpers detect overflow in addition, subtraction, multiplication, unary negation, and division/remainder, including division by zero and the minimum-integer divided by minus-one case. Global initializers remain constant C expressions checked by the strict backend. Expression chains longer than 512 operations are rejected.

The seed was regenerated and verified through stages 1, 2, and 3. Generated arithmetic diagnostics embed the source basename so checkout relocation does not change generated C. The CLI's self-rebuild compares C for both compiler and driver before publishing an executable.

## Allocation and code generation

The bootstrap runtime packs small immutable strings into 64 KiB chunks, gives large strings dedicated chunks, and caches known lengths in a bounded two-way cache. Empty concatenation and full-string slicing can reuse immutable storage. Arbitrary C literals and argument strings remain supported without reading metadata before their pointers. Repeated source reads deduplicate inode protection entries.

The full-language backend caches type mappings and formats ordinary output lines through a stack buffer. File input checks EOF before growing a buffer and tries to shrink successful strings to content length plus one. A 4,096-byte file requests 4,097 bytes rather than 8,193; an empty input line requests one rather than 64. These are requested capacities, not guaranteed RSS savings.

Sequencing and arithmetic checks enlarged the bootstrap C seed from about 26 KiB to 157 KiB. The release did not claim a universal speedup. [Measurements](../bench/README.md) explain the isolated workloads and their limits.

## Platform and installation

Executable discovery has Linux `/proc`, guarded macOS image API, and POSIX argv/PATH paths. A C profile forces the fallback without `/proc`. Assembly is selected only on Linux x86-64; other targets use C. The tested release platform was Linux x86-64/GCC, not every supported code path's OS.

Builds support checkout and compiler paths containing spaces or apostrophes. `CC` identifies one executable. Compiler binaries no longer embed absolute checkout paths for resource lookup. Child argument storage grows dynamically instead of stopping at 255 entries, subject to OS limits.

`selfhost/platform.h` is installed with rebuild resources. An unset `HOME` requires an explicit prefix. Installer output gives a safely quoted PATH suggestion.

## Migration and validation

Code that relied on the borrowing or read-only pointer defects is now rejected. Make mutable access explicit with `&mut`, and shorten the borrowing block when necessary. No full-language feature was intentionally removed.

The 0.4.1 validation run passed 272 checks, plus sanitizer, installation/relocation, fixed-point, and optimization-mode checks. This is a historical result; [current validation](validation.md) describes 0.4.2. [Repository update instructions](repository-update.md) list the exact additions and replacements relative to 0.4.0.
