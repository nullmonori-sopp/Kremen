# Kremen 0.4.0

Released on 2026-10-21. This release introduced a working compiler command-line driver written in the bootstrap subset of Kremen. `kremen selfhost` connected it to the normal installation.

The subset frontend gained its own type checking for `i64`, `bool`, and `string`: declarations, assignments, calls, operators, conditions, return types, and all-path returns. Names, scopes, arity, duplicates, literals, and the entry point were checked before reaching C. An implicit boolean-to-integer conversion was rejected even when C might accept it.

`toolchain.kr` implemented `check`, `emit-c`, `build`, `run`, and `bootstrap`. `host.c` supplied OS primitives: separate process arguments, launching without a shell, temporary directories, resource lookup, and atomic artifact publication. Both the compiler and CLI's generated C were compared against their next stage during self-rebuild.

The installer began installing the subset executable and rebuild sources. Output protection covered paths, symlinks, and hard links. Failed compilation preserved existing artifacts. Source loaders rejected FIFOs without waiting; additional fixes covered C-header name collisions and C11 trigraph preservation in string literals.

The full language kept its 0.3 syntax and C frontend. The subset did not gain full-language composite types, results, cleanup, or borrowing. Self-reproduction of a subset was not full self-hosting of the language. C tools and libc remained required.

See [0.4.1](v0.4.1.md) for subsequent correctness, allocation, and platform work, and [0.4.2](v0.4.2.md) for the current documentation and diagnostics update. Current commands are in [Self-hosting](selfhosting.md).
